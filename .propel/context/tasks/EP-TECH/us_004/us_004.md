# User Story - US_004

## Story ID
* ID Format: US_004

## Story Title
* Wire Prometheus, Grafana, and Seq structured logging observability

## Description
* As a **platform operator**, I want Prometheus scraping API metrics, Grafana displaying a base dashboard, and Seq receiving structured logs from the .NET API, so that I can detect and diagnose production issues without SSH access to containers.

## Acceptance Criteria

### AC-001: Prometheus successfully scrapes API metrics
- **Given**: The Docker Compose stack is running and the API is healthy
- **When**: Prometheus evaluates its scrape targets
- **Then**: The Prometheus UI at `http://localhost:9090/targets` shows the `api` target with `State: UP` and `Last Scrape: <30 seconds ago`

### AC-002: Grafana base dashboard loads with live data
- **Given**: Grafana is provisioned with the API metrics datasource and the base dashboard JSON
- **When**: The Grafana UI at `http://localhost:3000` is opened and the base dashboard is selected
- **Then**: The dashboard renders with at least three panels (request latency, error rate, uptime), each showing live data points within the last 5 minutes

### AC-003: Seq receives structured log events from the .NET API
- **Given**: The Serilog Seq sink is configured in `appsettings.json` pointing to the Seq container
- **When**: Any API endpoint is called (e.g., `GET /api/health`)
- **Then**: A structured log event with `SourceContext`, `RequestPath`, `StatusCode`, and `Elapsed` properties appears in Seq within 5 seconds, searchable via the Seq UI at `http://localhost:5341`

### AC-004: Seq receives audit log events as structured entries
- **Given**: An auditable action occurs (login, patient data access)
- **When**: The `IAuditLogger` service writes the event
- **Then**: A Seq log entry with `EventType: AuditLog`, `ActorId`, `ActionType`, `ResourceId`, and `OccurredAt` (UTC) properties is written within 2 seconds

## Edge Cases
* **Seq container not yet ready at API startup**: If the Seq sink fails to connect on first log write, Serilog must buffer events in memory (up to 500 events) and retry the connection; it must not crash the API process or drop the log entry silently.
* **Grafana datasource auto-provisioning failure**: If `prometheus.yml` scrape config points to an incorrect internal hostname, the Grafana datasource must show a descriptive error in the UI (`Error: could not connect to Prometheus`) rather than a blank dashboard.
