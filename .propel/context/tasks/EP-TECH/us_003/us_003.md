# User Story - US_003

## Story ID
* ID Format: US_003

## Story Title
* Scaffold .NET 8 Web API with health checks, Nginx TLS, and CI/CD skeleton

## Description
* As a **backend developer**, I want the ASP.NET Core .NET 8.0 Web API project scaffolded with a working middleware pipeline, health-check endpoint, Prometheus `/metrics` exposure, and Nginx TLS termination wired, so that feature teams can add controllers without touching infrastructure configuration.

## Acceptance Criteria

### AC-001: API health-check endpoint returns 200
- **Given**: The .NET API container is running inside the Docker Compose stack
- **When**: `GET https://localhost/api/health` is called
- **Then**: The response is HTTP 200 with body `{"status":"Healthy"}` within 2 seconds

### AC-002: Nginx reverse-proxies `/api/*` to the .NET container
- **Given**: Nginx is running and the `.NET API` container is reachable on the internal Docker network
- **When**: `GET https://localhost/api/health` is called from outside the Docker network
- **Then**: The response comes from the .NET API (verified by `X-Service: api` response header) and no request reaches the API over plain HTTP from outside the Docker bridge

### AC-003: Nginx TLS 1.2+ enforced — TLS 1.0 and 1.1 rejected
- **Given**: Nginx is configured with `ssl_protocols TLSv1.2 TLSv1.3`
- **When**: A client attempts to connect with TLS 1.0 or TLS 1.1
- **Then**: The connection is refused with an SSL handshake error

### AC-004: Prometheus `/metrics` endpoint is accessible
- **Given**: The `prometheus-net.AspNetCore` package is registered in the .NET middleware pipeline
- **When**: `GET https://localhost/api/metrics` is called from within the Docker network
- **Then**: The response is HTTP 200 with `Content-Type: text/plain; version=0.0.4` and at least the `http_requests_received_total` metric present

### AC-005: CI/CD GitHub Actions workflow runs lint + build on pull request
- **Given**: A pull request is opened against the `main` branch
- **When**: The `.github/workflows/ci.yml` GitHub Actions workflow triggers
- **Then**: The workflow completes all steps (lint, dotnet build, npm build, docker compose up --wait, smoke test against `/api/health`) with exit code 0 within 10 minutes

## Edge Cases
* **Missing `JWT_SECRET` environment variable**: If the `JWT_SECRET` env var is not injected at startup, the .NET API must fail fast with a startup exception message "JWT_SECRET is not configured" and exit with code 1 rather than starting with an insecure default.
* **CI Docker layer cache invalidation**: If `dotnet restore` fails due to NuGet rate limiting in CI, the workflow must retry the restore step once before failing the pipeline.
