# User Story - US_038

## Story ID
* ID Format: US_038

## Story Title
* Ollama entity extraction from document chunks with schema validation and de-duplication

## Description
* As a **platform system**, I want medical entities (diagnoses, medications, allergies, procedures) extracted from each document chunk via Ollama and de-duplicated before storage, so that the patient record is enriched with structured clinical facts without redundancy.

## Acceptance Criteria

### AC-001: Entity extraction is triggered when all chunks of a document have embeddings
- **Given**: All `chunk_embeddings` rows for a `document_id` are committed
- **When**: The `EntityExtractionService` consumes the `DocumentEmbeddingsComplete` event
- **Then**: For each document chunk, `POST /api/generate` is called on the Ollama local endpoint with a structured prompt instructing it to return only JSON of the form `{"entities": [{"type": "Diagnosis|Medication|Allergy|Procedure", "value": "<string>", "confidence": <0.0-1.0>}]}`

### AC-002: Ollama response is validated against the entity JSON schema before storage
- **Given**: The Ollama API returns a response for a chunk
- **When**: The entity extraction service parses the response
- **Then**: The JSON is validated against the expected schema; any response that is not valid JSON, is missing the `entities` key, or contains an entity with `type` outside the four allowed values is rejected, logged with `eventType = "EntityExtractionSchemaError"`, and not stored — processing continues to the next chunk

### AC-003: De-duplication prevents the same entity value being stored twice for the same patient
- **Given**: Chunks from two different documents for the same patient both contain the entity `{"type": "Diagnosis", "value": "Type 2 Diabetes"}`
- **When**: Both are processed by the extraction pipeline
- **Then**: Only one `patient_entities` row exists for `(patient_id, type="Diagnosis", value="Type 2 Diabetes")` — the second extraction updates the `last_seen_at` column rather than inserting a duplicate — verified by `SELECT COUNT(*) FROM patient_entities WHERE patient_id = <id> AND type = 'Diagnosis' AND value = 'Type 2 Diabetes'` returning 1

### AC-004: All extracted and validated entities are persisted with source document reference
- **Given**: 5 valid unique entities are extracted from a document
- **When**: The persistence step runs
- **Then**: 5 rows are inserted in `patient_entities` (or `last_seen_at` is updated for duplicates) with `patient_id`, `document_id`, `type`, `value`, `confidence`, and `created_at`

### AC-005: Document status is updated to "EntitiesExtracted" when pipeline completes
- **Given**: All chunks of a document have been processed (with or without entity results)
- **When**: The extraction pipeline finalises
- **Then**: `document_records.status` is updated to `"EntitiesExtracted"`

## Edge Cases
* **Ollama returns an empty entities array for a chunk**: An empty `{"entities": []}` response is valid — it must be accepted without error, and no rows are inserted for that chunk. The pipeline continues to the next chunk.
* **Confidence score below 0.5**: Entities with `confidence < 0.5` must still be stored but with a `low_confidence = true` flag on the `patient_entities` row — not silently dropped, so staff can review them.
