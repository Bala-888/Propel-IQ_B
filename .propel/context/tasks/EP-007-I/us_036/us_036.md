# User Story - US_036

## Story ID
* ID Format: US_036

## Story Title
* PdfPig text extraction with sliding window chunking for AI ingestion

## Description
* As a **platform system**, I want uploaded PDF documents to be decrypted, have their text extracted via PdfPig, and split into overlapping sliding window chunks, so that they are ready for downstream embedding and entity extraction.

## Acceptance Criteria

### AC-001: Text extraction is triggered when a document transitions to status "Uploaded"
- **Given**: A `document_records` row has `status = "Uploaded"` and `mime_type = "application/pdf"`
- **When**: The `DocumentTextExtractionService` consumes the `DocumentUploaded` event
- **Then**: The document is decrypted in memory using the stored per-document key, text is extracted using the PdfPig library, and the `document_records.status` is updated to `"TextExtracted"` — the decrypted bytes are never written to disk

### AC-002: Extracted text is split into chunks of ≤500 tokens with 50-token overlap
- **Given**: A document produces 2,000 tokens of extracted text
- **When**: The sliding window chunker processes the text
- **Then**: The resulting chunks each contain ≤500 tokens and consecutive chunks share a 50-token overlap — verified by asserting `chunks[i].endToken - chunks[i+1].startToken == 50` in the unit test

### AC-003: Chunks are persisted to the `document_chunks` table
- **Given**: Text extraction and chunking complete successfully
- **When**: The pipeline commits
- **Then**: One row per chunk is inserted in `document_chunks` with columns `document_id`, `chunk_index` (0-based), `content`, `token_count`, and `created_at` — `document_records.status` is updated to `"Chunked"`

### AC-004: Non-extractable PDF (e.g. scanned image-only) is flagged and does not crash the pipeline
- **Given**: A PDF document contains no selectable text (all pages are rasterised images)
- **When**: PdfPig extraction returns an empty string
- **Then**: `document_records.status` is updated to `"ExtractionFailed"` with `failure_reason = "NoTextContent"`, the event is logged to Seq with `level = "Warning"`, and the pipeline does not re-enqueue the document for infinite retry

## Edge Cases
* **Multi-page PDF with 300+ pages**: The extractor must process large documents page-by-page in a streaming fashion without loading all pages into memory simultaneously — heap usage must not spike above 500 MB for a single document.
* **DOCX file arrives in the chunking pipeline**: This service handles PDF only. DOCX extraction must be handled by a separate dedicated service. If a `document_records` row with `mime_type != "application/pdf"` reaches this service, it must be skipped with `level = "Warning"` logged — not silently corrupted.
