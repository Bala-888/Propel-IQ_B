# User Story - US_043

## Story ID
* ID Format: US_043

## Story Title
* RAG-based ICD-10 and CPT medical code suggestions from patient documents

## Description
* As a **clinician**, I want the system to suggest relevant ICD-10 diagnosis codes and CPT procedure codes derived from the patient's documents using RAG, so that coding is faster and more accurate without manual lookup.

## Acceptance Criteria

### AC-001: Code suggestions are generated when a clinician opens SCR-015 for a patient
- **Given**: An authenticated Clinician or Admin user navigates to `/patients/{id}/codes` (SCR-015)
- **When**: `GET /patients/{id}/code-suggestions` is called
- **Then**: The API performs a pgvector similarity search over the patient's `chunk_embeddings` using the patient's entity list as the query context, calls Ollama RAG to suggest codes, and returns a list of up to 10 `{"codeType": "ICD10 | CPT", "code": "<string>", "description": "<string>", "confidence": <0.0-1.0>, "supportingChunkIds": [<uuids>]}` objects within 10 seconds

### AC-002: ICD-10 codes conform to the ICD-10-CM format
- **Given**: Ollama returns an ICD-10 code suggestion
- **When**: The response is validated
- **Then**: Each ICD-10 code matches the pattern `[A-Z][0-9]{2}(\.[0-9A-Z]{1,4})?` — any code not matching this pattern is rejected and logged with `eventType = "InvalidCodeFormat"` before being returned to the caller

### AC-003: CPT codes conform to the 5-digit numeric format
- **Given**: Ollama returns a CPT code suggestion
- **When**: The response is validated
- **Then**: Each CPT code is exactly 5 digits (e.g., `99213`) — any code not matching `^\d{5}$` is rejected with `eventType = "InvalidCodeFormat"` logged

### AC-004: Supporting chunk IDs are returned and linked to the suggestion
- **Given**: A code suggestion is generated with evidence from 2 document chunks
- **When**: The suggestion is rendered on SCR-015
- **Then**: Each suggestion card shows the code, description, confidence score, and a "View Evidence" link that expands to display the referenced chunk text — clinician can verify the AI reasoning

### AC-005: Access is restricted to Clinician and Admin roles
- **Given**: A user with role `Patient` or `Staff` calls `GET /patients/{id}/code-suggestions`
- **When**: The RBAC middleware evaluates the request
- **Then**: The response is HTTP 403 — no code suggestions are returned

## Edge Cases
* **Patient has fewer than 3 document chunks**: If insufficient context exists for meaningful RAG retrieval (fewer than 3 chunks in `chunk_embeddings`), the API must return `{"suggestions": [], "message": "Insufficient document data for code suggestions. Please upload clinical documents first."}` — not an empty array without explanation.
* **Ollama returns a code with confidence < 0.3**: Low-confidence suggestions (confidence < 0.3) must still be returned but marked with a `"lowConfidence": true` flag — not silently dropped. The clinician decides whether to accept them.
