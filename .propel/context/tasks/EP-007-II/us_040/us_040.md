# User Story - US_040

## Story ID
* ID Format: US_040

## Story Title
* 360-degree patient view aggregation API and React UI

## Description
* As a **staff member or clinician**, I want to view a consolidated 360-degree summary of a patient's medical history, extracted entities, active bookings, and documents on one screen, so that I can understand the patient's full clinical picture without navigating multiple systems.

## Acceptance Criteria

### AC-001: Patient search on SCR-013 returns results within 500ms
- **Given**: An authenticated Staff, Admin, or Clinician user types at least 3 characters in the patient search field on SCR-013
- **When**: `GET /patients/search?q=<term>` is called
- **Then**: Matching patients are returned within 500ms, each result showing full name, DOB, and patient ID — the list is limited to 20 results max

### AC-002: Navigating to a patient record loads the 360-degree view on SCR-014
- **Given**: A staff member selects a patient from the search results on SCR-013
- **When**: The browser navigates to `/patients/{id}/view` (SCR-014)
- **Then**: `GET /patients/{id}/summary` is called and returns an aggregated payload including: demographics, entity list (diagnoses, medications, allergies, procedures), active bookings, and document list — all rendered within SCR-014 in ≤2 seconds for a patient with up to 50 documents

### AC-003: Summary API aggregates data from multiple tables in a single response
- **Given**: `GET /patients/{id}/summary` is called
- **When**: The aggregation query executes
- **Then**: The response contains a flat JSON object with keys `demographics`, `entities` (array), `activeBookings` (array), and `documents` (array) — no more than 3 database round trips are used to build the response (use LEFT JOIN or separate queries batched in a single transaction)

### AC-004: Access to patient summary is restricted to Staff, Admin, and Clinician roles
- **Given**: A user with role `Patient` calls `GET /patients/{otherId}/summary`
- **When**: The RBAC middleware evaluates the request
- **Then**: The response is HTTP 403 with `{"error": "Access denied."}` — no patient data is returned

## Edge Cases
* **Patient has no extracted entities**: If `patient_entities` returns an empty array for the patient, the `entities` section on SCR-014 must display "No clinical entities extracted yet." — not a blank panel.
* **Patient has 100+ documents**: The documents list must be paginated (default page size 20) on SCR-014 — all documents must not be loaded into memory at once.
