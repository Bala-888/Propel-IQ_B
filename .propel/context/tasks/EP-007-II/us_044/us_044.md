# User Story - US_044

## Story ID
* ID Format: US_044

## Story Title
* Clinician accepts, rejects, or corrects RAG medical code suggestions with human-in-loop review

## Description
* As a **clinician**, I want to accept, reject, or manually correct each suggested medical code before it is finalised on the patient record, so that the AI serves as an assistant and final coding decisions always rest with a qualified human.

## Acceptance Criteria

### AC-001: Each suggestion on SCR-015 has Accept, Reject, and Correct actions
- **Given**: A code suggestion is rendered on SCR-015 (Medical Code Review)
- **When**: The clinician views the suggestion card
- **Then**: Three inline actions are available per suggestion: "Accept" (check icon), "Reject" (cross icon), and "Correct" (edit icon) — all with accessible aria-labels and keyboard focusability

### AC-002: Accepting a suggestion creates a confirmed medical code record
- **Given**: The clinician clicks "Accept" on a code suggestion
- **When**: `POST /patients/{id}/medical-codes` is called with `{"codeType": "ICD10", "code": "<string>", "source": "AI", "reviewStatus": "Accepted", "reviewedBy": "<userId>"}`
- **Then**: The response is HTTP 201, a `patient_medical_codes` row is inserted with `review_status = "Accepted"`, `reviewed_by`, and `reviewed_at`, and an audit log entry `ActionType: MedicalCodeAccepted` is written

### AC-003: Rejecting a suggestion marks the suggestion as rejected without creating a code record
- **Given**: The clinician clicks "Reject" on a suggestion
- **When**: `PATCH /code-suggestions/{suggestionId}` is called with `{"reviewStatus": "Rejected", "reviewedBy": "<userId>"}`
- **Then**: The suggestion is marked `review_status = "Rejected"` in the suggestions table, no `patient_medical_codes` row is created, the suggestion card is visually struck through and marked "Rejected" with an icon, and an audit entry `ActionType: MedicalCodeRejected` is written

### AC-004: Correcting a suggestion opens an inline edit and saves the corrected code
- **Given**: The clinician clicks "Correct" on a suggestion
- **When**: An inline edit field appears pre-filled with the AI-suggested code
- **Then**: The clinician can modify the code value and submit — `POST /patients/{id}/medical-codes` is called with `{"source": "AI-Corrected", "reviewStatus": "Corrected", "correctedCode": "<newCode>"}` — a `patient_medical_codes` row is created with the corrected code and `source = "AI-Corrected"`, and an audit entry `ActionType: MedicalCodeCorrected` is written with both original and corrected values

### AC-005: Submitted corrected code is validated against ICD-10 and CPT format rules
- **Given**: A clinician enters an invalid code (e.g., `"XYZ"`) in the correction field
- **When**: The correction form is submitted
- **Then**: The submission is blocked with inline error "Invalid code format. ICD-10 codes must match [A-Z][0-9]{2}(.[…]) and CPT codes must be 5 digits." — the error must not clear the entered value

## Edge Cases
* **Clinician attempts to accept a suggestion already accepted by another user**: If `review_status != "Pending"` when the accept call arrives, the API must return HTTP 409 with `{"error": "This suggestion has already been reviewed."}` — no duplicate `patient_medical_codes` row must be created.
* **All suggestions rejected**: If a clinician rejects all suggestions, the UI must display "All suggestions have been reviewed. No codes were added." — not a blank empty state that implies an error.
