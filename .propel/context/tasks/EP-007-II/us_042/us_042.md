# User Story - US_042

## Story ID
* ID Format: US_042

## Story Title
* Staff conflict resolution action to resolve or dismiss clinical conflicts

## Description
* As a **clinician or staff member**, I want to resolve or dismiss a detected clinical conflict from the patient view, so that addressed conflicts are removed from the active queue and an audit trail is maintained.

## Acceptance Criteria

### AC-001: Resolve Conflict drawer opens from the conflict row on SCR-014
- **Given**: A staff member is viewing SCR-014 and sees an Open conflict in the Conflicts panel
- **When**: The staff member clicks "Resolve" on a conflict row
- **Then**: MOD-005 (Resolve Conflict Drawer) opens with the conflict details pre-populated, a `Resolution Note` text area, and two action buttons: "Mark Resolved" and "Dismiss"

### AC-002: "Mark Resolved" updates conflict status and logs the action
- **Given**: The staff member enters a resolution note and clicks "Mark Resolved"
- **When**: `PATCH /clinical-conflicts/{id}/resolve` is called with `{"resolution": "Resolved", "note": "<text>"}`
- **Then**: The response is HTTP 200, `clinical_conflicts.status` is updated to `"Resolved"`, `resolved_by` is set to the acting user ID, `resolved_at` is set to the server timestamp, and an audit log entry `ActionType: ConflictResolved` is written with the note

### AC-003: "Dismiss" updates conflict status with a dismissal note
- **Given**: The staff member clicks "Dismiss" without entering a resolution note
- **When**: `PATCH /clinical-conflicts/{id}/resolve` is called with `{"resolution": "Dismissed"}`
- **Then**: `clinical_conflicts.status` is updated to `"Dismissed"` and an audit log entry `ActionType: ConflictDismissed` is written — a note is optional for dismissal

### AC-004: Resolved and dismissed conflicts are removed from the SCR-014 Open conflicts panel
- **Given**: A conflict is updated to `status = "Resolved"` or `"Dismissed"`
- **When**: `GET /patients/{id}/summary` is next called
- **Then**: The resolved/dismissed conflict no longer appears in the `conflicts` array — only `status = "Open"` conflicts are returned by default

## Edge Cases
* **Staff attempts to resolve an already-resolved conflict**: If `PATCH /clinical-conflicts/{id}/resolve` is called for a conflict with `status != "Open"`, the API must return HTTP 409 with `{"error": "This conflict has already been resolved or dismissed."}` — no update is made.
* **Resolution note exceeds 1,000 characters**: The `note` field must be validated server-side — any note exceeding 1,000 characters must return HTTP 400 with `{"error": "Resolution note must be 1,000 characters or fewer."}`.
