# User Story - US_019

## Story ID
* ID Format: US_019

## Story Title
* Display available appointment slots with date, time, and availability status

## Description
* As a **patient**, I want to see a list of available appointment slots with dates, times, and statuses on the booking screen, so that I can pick a slot that fits my schedule before committing to a booking.

## Acceptance Criteria

### AC-001: API returns only Available slots
- **Given**: The `appointment_slots` table contains slots with statuses `Available`, `Booked`, and `Blocked`
- **When**: `GET /slots?available=true` is called by an authenticated patient
- **Then**: The response is HTTP 200 with a JSON array containing only slots where `status = "Available"` — no Booked or Blocked slots are included

### AC-002: Slot listing is paginated
- **Given**: 50 available slots exist in the database
- **When**: `GET /slots?available=true&page=1&pageSize=10` is called
- **Then**: The response contains exactly 10 slots and a `pagination` object with `{"total": 50, "page": 1, "pageSize": 10, "totalPages": 5}`

### AC-003: React calendar view displays slots grouped by day
- **Given**: Available slots span 5 calendar days
- **When**: The appointment booking screen (SCR-006) renders
- **Then**: Slots are displayed grouped by date, each showing the time, duration in minutes, and an "Available" label — no Booked or Blocked slots appear in the calendar grid

### AC-004: Selecting a slot highlights it and enables the "Book" button
- **Given**: The patient is on SCR-006 and available slots are displayed
- **When**: A time slot is clicked
- **Then**: The slot cell becomes visually highlighted with a `--color-primary-subtle` background and the "Book this slot" button becomes enabled (not disabled)

## Edge Cases
* **No available slots**: If `GET /slots?available=true` returns an empty array, SCR-006 must display "No available slots at this time. Please check back later or add yourself to a wait list." — not a blank calendar grid.
* **Slot becomes booked between page load and selection**: The available status is fetched on page load; if a slot is booked by another patient between load and the user's booking attempt, the booking step (us_020) must handle the 409 conflict — this screen only shows the initial state.
