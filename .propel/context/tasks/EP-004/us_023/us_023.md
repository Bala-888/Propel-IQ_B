# User Story - US_023

## Story ID
* ID Format: US_023

## Story Title
* Soft insurance pre-check with non-blocking alert on booking screen

## Description
* As a **patient**, I want to be alerted when my insurance information may be missing or incomplete before I confirm my booking, so that I can update it in time without being blocked from booking.

## Acceptance Criteria

### AC-001: Insurance pre-check runs before the booking confirmation dialog opens
- **Given**: A patient selects a slot on SCR-006 and clicks "Book this slot"
- **When**: `GET /insurance/pre-check?patientId=<id>` is called
- **Then**: The response is returned within 2 seconds and contains `{"status": "Complete" | "Incomplete" | "Missing"}` based on the patient's `InsuranceRecord`

### AC-002: Missing insurance triggers a soft non-blocking alert and allows booking to proceed
- **Given**: The pre-check API returns `{"status": "Missing"}`
- **When**: The patient is shown MOD-002 (Booking Confirmation Dialog)
- **Then**: A soft alert banner reading "Insurance information is missing. You can still book, but please update it before your appointment." is displayed at the top of the dialog, the "Confirm Booking" button remains enabled, and the patient can proceed without resolving the alert

### AC-003: Complete insurance record produces no alert
- **Given**: The pre-check API returns `{"status": "Complete"}`
- **When**: MOD-002 is rendered
- **Then**: No insurance alert is displayed and the dialog shows only the slot confirmation details

### AC-004: Pre-check result is logged for audit
- **Given**: Any pre-check call is executed
- **When**: The controller returns a response
- **Then**: An audit log entry is written with `ActionType: InsurancePreCheck`, `patientId`, and `result` — regardless of the outcome

## Edge Cases
* **Pre-check API is unavailable**: If `GET /insurance/pre-check` returns a 5xx error, the booking flow must continue without the soft alert — the error must not block the patient from booking. The failure must be logged but must not surface an error message in the UI.
* **Incomplete vs. Missing distinction**: `Incomplete` means a record exists but required fields (e.g., policy number) are blank. The alert for `Incomplete` reads "Insurance information may be incomplete." to distinguish it from the `Missing` message.
