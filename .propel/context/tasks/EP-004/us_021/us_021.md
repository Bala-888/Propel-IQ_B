# User Story - US_021

## Story ID
* ID Format: US_021

## Story Title
* Compute and persist patient no-show risk score at booking time

## Description
* As a **clinic administrator**, I want a no-show risk score computed and stored for every new booking, so that staff can proactively intervene with high-risk patients to reduce appointment gaps.

## Acceptance Criteria

### AC-001: Risk score is computed and stored on every new booking creation
- **Given**: A confirmed booking record is created by us_020
- **When**: The `BookingCreated` domain event is handled by the `NoShowRiskScoringService`
- **Then**: A risk score in the range 0.00–1.00 is computed using at least `no_show_history_count`, `days_to_appointment`, and `booking_lead_time_days` fields, and stored in the `bookings.no_show_risk_score` column within 5 seconds of booking confirmation

### AC-002: Risk tier is derived from score thresholds
- **Given**: A risk score has been computed and stored
- **When**: The booking record is read back
- **Then**: The `no_show_risk_tier` column is set to `"Low"` for score < 0.40, `"Medium"` for 0.40–0.69, and `"High"` for ≥ 0.70

### AC-003: Risk score does not block or delay the booking confirmation response
- **Given**: The risk scoring pipeline executes asynchronously
- **When**: The booking API `POST /bookings` is called
- **Then**: The HTTP 201 response is returned to the patient without waiting for the risk score to be computed — no latency regression on the booking endpoint

### AC-004: Scoring failure is logged and does not corrupt the booking record
- **Given**: The risk scoring service throws an unhandled exception
- **When**: The `BookingCreated` domain event handler encounters the error
- **Then**: The exception is logged to Seq with `level = "Error"` and `eventType = "RiskScoringFailed"`, the booking record retains `no_show_risk_score = null` and `no_show_risk_tier = "Unknown"`, and no retry leaves a duplicate booking

## Edge Cases
* **First-time patient with no history**: If `no_show_history_count = 0` and no prior booking records exist, the scorer must produce a score between 0.00 and 0.40 (Low tier) using only appointment-lead-time features — it must not return null or throw a divide-by-zero error.
* **Risk score recomputation on reschedule**: When a booking's slot is changed (rescheduled), the `no_show_risk_score` and `no_show_risk_tier` must be recomputed from the new `days_to_appointment` value — the old score must not persist.
