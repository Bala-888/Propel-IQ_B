# User Story - US_016-I

## Story ID
* ID Format: US_016-I

## Story Title
* AI conversational intake — Part I: multi-turn Ollama dialogue engine

## Description
* As a **patient**, I want to complete my pre-visit intake through a natural-language chat interface powered by a local AI, so that I can provide my health history conversationally without filling out a complex form.

## Acceptance Criteria

### AC-001: AI session is initiated and first question delivered
- **Given**: An authenticated patient navigates to the AI intake screen (SCR-004) and taps "Start AI Intake"
- **When**: `POST /intake/ai/start` is called with the patient's ID
- **Then**: The API returns HTTP 200 with `{"sessionId": "<uuid>", "message": "Hello! I'm here to help collect your health history..."}` within 3 seconds and the chat message appears in the UI

### AC-002: Multi-turn dialogue collects all 5 required fields
- **Given**: An active AI intake session exists
- **When**: The patient responds to successive prompts covering demographics, medical history, current medications, allergies, and chief complaint
- **Then**: After the final exchange, `POST /intake/ai/message` returns a response with `{"allFieldsCollected": true, "summary": {...}}` where the summary object contains non-null values for all 5 field groups

### AC-003: Ollama inference executes locally — no external HTTP calls
- **Given**: A network monitor is attached to the Docker bridge
- **When**: An AI intake session processes a patient message
- **Then**: All inference HTTP requests are directed to `http://ollama:11434/api/chat` (internal Docker network) and zero requests are made to any external IP address

### AC-004: AI handles colloquial health descriptions
- **Given**: A patient types "my knee has been killing me for weeks"
- **When**: The Ollama model processes the turn
- **Then**: The extracted chief complaint in the session state includes "knee pain" (not a literal quote) and the AI follows up with a clarifying question about duration or severity

### AC-005: Intake API auto-saves a draft after each turn
- **Given**: An active AI intake session has received at least 2 patient responses
- **When**: `POST /intake/ai/message` processes the 2nd response
- **Then**: An `IntakeRecord` with `status = "Draft"` exists in the database for this patient, containing the encrypted partial intake data collected so far

## Edge Cases
* **Ollama model not yet loaded**: If `POST http://ollama:11434/api/chat` returns HTTP 503 (model not ready), the API must return HTTP 503 with `{"error": "AI intake is temporarily unavailable. You can use the manual form instead."}` and an option to switch to manual mode must be displayed on SCR-004.
* **Inference timeout**: If the Ollama call does not return within 30 seconds, the request must be cancelled, and the user must see "The AI took too long to respond. Please try your message again." — the session must remain open and recoverable.
