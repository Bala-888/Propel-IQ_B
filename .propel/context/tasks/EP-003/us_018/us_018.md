# User Story - US_018

## Story ID
* ID Format: US_018

## Story Title
* Intake mode switch between AI and manual form without data loss

## Description
* As a **patient**, I want to switch between the AI conversational intake and the manual form at any point during my session, so that I can choose the input method that works best for me without losing any data I have already entered.

## Acceptance Criteria

### AC-001: Switching from AI mode to manual pre-populates manual form fields
- **Given**: A patient has collected Demographics and Medical History in the AI chat session
- **When**: `POST /intake/mode-switch` is called with `{"from": "AI", "to": "Manual", "sessionId": "<id>"}`
- **Then**: The API returns HTTP 200 and the manual form (SCR-005) opens with the Demographics and Medical History sections pre-populated from the AI-collected data — the patient does not need to re-enter those fields

### AC-002: Switching from manual to AI mode resumes from where the patient left off
- **Given**: A patient has filled Demographics and Medications in the manual form
- **When**: `POST /intake/mode-switch` is called with `{"from": "Manual", "to": "AI"}`
- **Then**: The AI session on SCR-004 acknowledges the prior data and skips already-completed fields in subsequent dialogue turns — it does not ask for the patient's name again

### AC-003: Fields with no equivalent in the target mode are preserved in a review buffer
- **Given**: A patient entered a free-text note in the AI chat that does not map to a named manual field
- **When**: The mode switch completes
- **Then**: The unmapped content is preserved in a "Review items" section in the target mode and the patient is notified "Some items could not be auto-mapped. Please review them."

### AC-004: Mode switch button is visible and accessible at all points during intake
- **Given**: A patient is on either SCR-004 (AI) or SCR-005 (Manual)
- **When**: The intake screen is rendered
- **Then**: A "Switch to [other mode]" button is visible in the toolbar, meets 44×44px touch target, and is focusable via keyboard Tab

## Edge Cases
* **Switching modes with no data entered**: If the patient clicks "Switch mode" immediately after starting with no data entered, the mode switch must succeed without error and the target form must open empty — no mapping or buffer logic is invoked.
* **Concurrent session write during mode switch**: If a background auto-save fires at the same moment as the mode-switch API call, the mode-switch must win and the auto-save must use the latest combined state, not overwrite the switch result.
