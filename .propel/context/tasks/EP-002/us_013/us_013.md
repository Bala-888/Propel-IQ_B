# User Story - US_013

## Story ID
* ID Format: US_013

## Story Title
* RBAC middleware and HIPAA access control enforcement on all API endpoints

## Description
* As a **security engineer**, I want every API endpoint protected by role-based access control enforced at the middleware layer, with unauthorized access attempts blocked and logged, so that patients cannot access staff data, staff cannot access admin functions, and no PHI is exposed to unintended roles.

## Acceptance Criteria

### AC-001: Patient cannot access staff-only queue endpoint
- **Given**: A Patient JWT is used in the Authorization header
- **When**: `GET /dashboard/staff` is called
- **Then**: The response is HTTP 403 with `{"error": "Access denied. Insufficient role."}` and no patient data is returned

### AC-002: Unauthenticated request to a protected resource returns 401
- **Given**: No Authorization header is present
- **When**: `GET /patients/123/view` is called
- **Then**: The response is HTTP 401 with `{"error": "Authentication required."}` and the client is directed to `/login`

### AC-003: Patient can only access their own patient record
- **Given**: Patient A (id=1) is authenticated
- **When**: `GET /patients/2/view` is called (Patient B's record)
- **Then**: The response is HTTP 403 with `{"error": "Access denied. You can only access your own records."}` and no data from Patient B is returned

### AC-004: Admin-only endpoint rejects Staff role
- **Given**: A Staff JWT is used
- **When**: `GET /admin/metrics` is called
- **Then**: The response is HTTP 403 and an audit log entry with `ActionType: UnauthorizedAccess`, `ResourceType: AdminMetrics`, `ActorRole: Staff` is written

### AC-005: Three unauthorized attempts from same IP trigger admin alert
- **Given**: Three HTTP 403 responses have been generated for the same source IP within 10 minutes
- **When**: The fourth unauthorized attempt is detected
- **Then**: An alert entry is written to the admin notifications table with `alertType: RepeatedUnauthorizedAccess` and `sourceIp` — visible in the admin KPI dashboard

## Edge Cases
* **Patient accessing their own record after partial token expiry**: If the access token has just expired but the RBAC check would pass, the middleware must return HTTP 401 (token expired) rather than HTTP 403 (access denied) so the client can trigger the correct refresh flow.
* **Role changed after token issued**: If a user's role is changed from Staff to Patient while they have an active JWT, the old token's role claim must be rejected on the next API call — the API must validate the `role` claim against the current database role and return HTTP 401 if they differ.
