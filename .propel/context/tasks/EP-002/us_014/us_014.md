# User Story - US_014

## Story ID
* ID Format: US_014

## Story Title
* Immutable audit log middleware with Seq structured event emission

## Description
* As a **compliance officer**, I want every sensitive platform action automatically captured in an immutable audit log and emitted as a structured Seq event, so that I can demonstrate HIPAA audit control compliance (§164.312(b)) and investigate any data access or modification without relying on application logs that could be altered.

## Acceptance Criteria

### AC-001: Audit log entry written for every patient data access
- **Given**: A Staff user calls `GET /patients/42/view`
- **When**: The `PostgresAuditLogger` middleware intercepts the request post-authorization
- **Then**: A row is inserted into `audit_logs` with `actorId`, `actorRole = "Staff"`, `actionType = "PatientDataAccess"`, `resourceType = "Patient"`, `resourceId = "42"`, `ipAddress`, `userAgent`, and `occurredAt` (UTC) within 100 ms of the response being sent

### AC-002: Audit entry blocks action on write failure
- **Given**: The PostgreSQL connection is temporarily unavailable when an auditable action is attempted
- **When**: The `IAuditLogger.RecordAsync(...)` call fails
- **Then**: The API returns HTTP 503 with `{"error": "Action could not be completed. Audit logging unavailable."}` and the underlying action (e.g., patient data read) is NOT completed

### AC-003: Seq receives a structured audit event matching the DB entry
- **Given**: An audit log entry is written to the database
- **When**: The Serilog Seq sink flushes
- **Then**: A Seq event with `EventType: AuditLog`, `ActionType`, `ActorId`, `ResourceId`, and `OccurredAt` properties is queryable in the Seq UI within 5 seconds

### AC-004: `app_user` role cannot delete or update audit_log rows (re-enforcement test)
- **Given**: The middleware has written an audit entry
- **When**: Any application-layer code path attempts `DELETE FROM audit_logs WHERE id = <id>` or `UPDATE audit_logs SET action_type = 'Modified'`
- **Then**: PostgreSQL raises a permission error and the operation is rolled back with no change to the audit entry

### AC-005: Audit events cover all required action types
- **Given**: The full set of auditable actions (login success, login failure, registration, patient data access, booking create/modify, document upload, code suggestion accept/reject, admin user CRUD, unauthorized access)
- **When**: Each action is performed once in an integration test suite
- **Then**: All 10 action types appear in `audit_logs` with non-null `actorId`, `actionType`, and `occurredAt` values

## Edge Cases
* **Audit log for system-initiated actions**: Background jobs (slot monitor, reminder scheduler) must write audit entries with `actorId = "system"` and `actorRole = "System"` — not null — to ensure complete coverage.
* **Audit log concurrent write under load**: Under 50 concurrent requests, all audit log INSERTs must succeed without deadlock. The audit table must use a sequence-based primary key (not UUID v4) to minimise index fragmentation on high-insert workloads.
