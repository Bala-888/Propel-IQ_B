# User Story - US_028

## Story ID
* ID Format: US_028

## Story Title
* Sync confirmed booking to Google Calendar and Outlook Calendar

## Description
* As a **patient**, I want my confirmed appointment automatically added to my Google or Outlook calendar, so that my personal calendar is always up to date without manual entry.

## Acceptance Criteria

### AC-001: Google Calendar event is created after booking confirmation
- **Given**: A patient has connected their Google account (OAuth 2.0 token stored) and has a Confirmed booking
- **When**: `POST /calendar/sync` is called with `{"provider": "Google", "bookingId": "<id>"}`
- **Then**: The Google Calendar API `POST /calendars/primary/events` is called with the correct `summary`, `start`, `end`, and `description` fields, the API returns HTTP 200, and the resulting `googleEventId` is stored in the `booking_calendar_sync` table

### AC-002: Outlook Calendar event is created after booking confirmation
- **Given**: A patient has connected their Microsoft account (OAuth 2.0 token stored) and has a Confirmed booking
- **When**: `POST /calendar/sync` is called with `{"provider": "Outlook", "bookingId": "<id>"}`
- **Then**: The Microsoft Graph API `POST /me/events` is called with the correct event fields, the API returns HTTP 201, and the resulting `outlookEventId` is stored in the `booking_calendar_sync` table

### AC-003: Calendar event is updated when booking is rescheduled
- **Given**: A patient has a synced Google Calendar event for their booking
- **When**: The booking is rescheduled to a new slot
- **Then**: `PATCH /calendars/primary/events/{googleEventId}` is called with the updated `start` and `end` times — no duplicate event is created

### AC-004: Calendar event is deleted when booking is cancelled
- **Given**: A synced calendar event exists for a confirmed booking
- **When**: The booking is cancelled
- **Then**: The corresponding calendar API `DELETE` call is made and the `booking_calendar_sync` row is marked `status = "Deleted"`

### AC-005: Calendar sync failure does not affect booking status
- **Given**: The Google Calendar API returns a 5xx error
- **When**: The sync service processes the `BookingConfirmed` event
- **Then**: The booking remains in `status = "Confirmed"`, the error is logged to Seq with `eventType = "CalendarSyncFailed"`, and a retry is queued — the patient's booking confirmation is not rolled back

## Edge Cases
* **OAuth token is expired at sync time**: The sync service must attempt a token refresh using the stored refresh token before making the calendar API call. If the refresh also fails, the sync is skipped and the patient is shown a banner on SCR-007 "Calendar sync unavailable. Please reconnect your calendar in Settings."
* **Booking confirmation page accessed before sync completes**: SCR-007 must render the confirmation details immediately without waiting for calendar sync — calendar sync status is a background concern.
