# User Story - US_029

## Story ID
* ID Format: US_029

## Story Title
* Manage notification and calendar sync opt-out preferences

## Description
* As a **patient**, I want to control which notification channels and calendar integrations are active for my account, so that I only receive communications I have explicitly consented to.

## Acceptance Criteria

### AC-001: Preference toggles are visible and interactive on SCR-008
- **Given**: An authenticated patient navigates to SCR-008 (Patient Profile & Settings)
- **When**: The Notifications section renders
- **Then**: Individual toggle switches are displayed for: Email Reminders, SMS Reminders, Slot Swap Notifications, Google Calendar Sync, and Outlook Calendar Sync — each reflecting the current saved preference

### AC-002: Toggling a preference persists immediately via PATCH
- **Given**: A patient flips the "SMS Reminders" toggle from ON to OFF
- **When**: The toggle change event fires
- **Then**: `PATCH /patients/{id}/preferences` is called with `{"sms_notifications_enabled": false}`, the response is HTTP 200, and the toggle reflects the saved OFF state — no page reload required

### AC-003: Disabling a notification channel prevents future dispatches
- **Given**: A patient has set `sms_notifications_enabled = false`
- **When**: Any downstream service (us_026, us_027) checks the preference before dispatching
- **Then**: The SMS is not sent and Seq records `eventType = "SmsSkipped"` with `reason = "OptedOut"` — the patient does not receive an SMS for any event

### AC-004: Preferences are initialised to opt-in defaults on account creation
- **Given**: A new patient account is created
- **When**: The `patient_preferences` row is inserted
- **Then**: All notification channels default to `enabled = true` and all calendar syncs default to `enabled = false` — consistent with privacy-by-default and opt-in sync model

## Edge Cases
* **PATCH request fails (network error)**: The UI must revert the toggle to its previous state and display a toast "Could not save your preference. Please try again." — the toggle must not remain in the new position if the API call failed.
* **Patient attempts to disable all channels**: Disabling all notification channels is allowed — the system must not show a mandatory consent warning or force at least one channel to remain enabled.
