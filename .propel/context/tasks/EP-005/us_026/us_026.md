# User Story - US_026

## Story ID
* ID Format: US_026

## Story Title
* Dispatch slot swap notifications via email, SMS, and PDF after successful preferred slot swap

## Description
* As a **patient**, I want to receive an email, SMS, and PDF notification when I am automatically moved to my preferred appointment slot, so that I know my booking has changed and have the updated confirmation details.

## Acceptance Criteria

### AC-001: Email notification is sent within 60 seconds of a SlotSwapCompleted event
- **Given**: A `SlotSwapCompleted` domain event is raised by us_025
- **When**: The `SlotSwapNotificationService` handles the event
- **Then**: The patient receives an email with subject `"Your appointment has been updated – <NewDate>"`, containing the new slot date/time, clinic address, and new booking reference — delivered within 60 seconds

### AC-002: SMS notification is sent concurrently with the email
- **Given**: The patient's phone number and SMS opt-in flag are both set
- **When**: The `SlotSwapNotificationService` handles the event
- **Then**: An SMS is dispatched via the configured SMTP-to-SMS gateway with content `"Your UPACIP appointment has been moved to <NewDate> <NewTime>. Ref: <BookingId>"` — sent concurrently with the email, not sequentially

### AC-003: A QuestPDF updated confirmation PDF is attached to the email
- **Given**: The QuestPDF generation pipeline renders the updated confirmation
- **When**: The email is composed
- **Then**: A PDF attachment named `updated-confirmation-<newBookingId>.pdf` is included, containing all mandatory booking fields defined in us_022 AC-002

### AC-004: Notifications are skipped for opted-out channels
- **Given**: A patient has `sms_notifications_enabled = false` but `email_notifications_enabled = true`
- **When**: The `SlotSwapNotificationService` processes the event
- **Then**: An email is sent, no SMS is dispatched, and the Seq log records `eventType = "SmsSkipped"` with `reason = "OptedOut"`

## Edge Cases
* **Both email and SMS dispatch fail on all 3 retries**: The notification service must log `eventType = "SlotSwapNotificationFailed"` with full error details but must not revert the slot swap — the booking change is committed regardless of notification outcome.
* **Patient prefers another slot while the swap notification is in-flight**: The notification must send the correct details matching the newly swapped slot, not the old booking — the notification payload must be built from the confirmed new booking record, not from the event payload alone.
