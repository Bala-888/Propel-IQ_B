# User Story - US_005

## Story ID
* ID Format: US_005

## Story Title
* Bootstrap PostgreSQL with pgcrypto, pgvector, and all 12 domain entity migrations

## Description
* As a **backend developer**, I want the PostgreSQL database bootstrapped with the pgcrypto and pgvector extensions and all 12 domain entity tables migrated via EF Core, so that every feature epic has a production-ready schema with the correct column types, FK constraints, and vector index from day one.

## Acceptance Criteria

### AC-001: Extensions provisioned on first migration run
- **Given**: A fresh PostgreSQL 15.3+ container with the `app` database created
- **When**: `dotnet ef database update` is executed
- **Then**: `SELECT extname FROM pg_extension` returns both `pgcrypto` and `vector`, confirming both extensions are installed

### AC-002: All 12 entity tables exist with correct primary keys
- **Given**: The EF Core migrations have been applied
- **When**: `SELECT table_name FROM information_schema.tables WHERE table_schema = 'public'` is executed
- **Then**: All 12 tables are present: `users`, `patients`, `intake_records`, `appointment_slots`, `bookings`, `clinical_documents`, `extracted_records`, `chunk_embeddings`, `medical_code_suggestions`, `audit_logs`, `reminder_schedules`, `insurance_records`

### AC-003: pgvector ivfflat cosine index exists on `chunk_embeddings.embedding`
- **Given**: The schema migration has completed
- **When**: `SELECT indexname FROM pg_indexes WHERE tablename = 'chunk_embeddings'` is executed
- **Then**: A row with `indexname LIKE '%ivfflat%'` is returned
- **And**: The index was created with `vector_cosine_ops` as confirmed by `pg_index` catalog entry

### AC-004: FK constraints enforced — orphaned booking blocked
- **Given**: No patient with ID `999` exists in `patients`
- **When**: An INSERT into `bookings` with `patient_id = 999` is attempted
- **Then**: PostgreSQL raises a foreign key violation error and the INSERT is rejected

### AC-005: EF Core `__EFMigrationsHistory` table populated
- **Given**: The initial migration has run
- **When**: `SELECT migration_id FROM "__EFMigrationsHistory"` is executed
- **Then**: At least one row exists with a `migration_id` matching the initial migration name (e.g., `20260101000000_InitialSchema`)

## Edge Cases
* **Re-running migration on an already-migrated database**: `dotnet ef database update` must be idempotent — running it a second time must complete with `No migrations were applied` and exit code 0 without modifying existing data.
* **pgvector extension not available**: If the PostgreSQL image does not include pgvector (e.g., plain `postgres:15`), the migration must fail with a clear error message `Extension "vector" is not available` rather than silently creating the column without the index.
