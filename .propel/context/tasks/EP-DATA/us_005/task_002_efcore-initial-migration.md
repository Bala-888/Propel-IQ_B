# Task - TASK_002

## Requirement Reference
- **User Story:** us_005
- **Story Location:** .propel/context/tasks/EP-DATA/us_005/us_005.md
- **Acceptance Criteria:**
  - AC-001: `pgcrypto` and `vector` extensions are present in `pg_extension` after first migration run
  - AC-002: All 12 tables exist in `information_schema.tables WHERE table_schema = 'public'` after migration
  - AC-003: `pg_indexes` for `chunk_embeddings` contains an entry matching `%ivfflat%` created with `vector_cosine_ops`
  - AC-004: FK violation raised when inserting a `bookings` row with a non-existent `patient_id` — FK DDL is emitted by EF Core from the Fluent API config in task_001
  - AC-005: `SELECT migration_id FROM "__EFMigrationsHistory"` returns at least one row matching `YYYYMMDDHHMMSS_InitialSchema`
- **Edge Cases:**
  - Re-running migration on already-migrated database: `dotnet ef database update` must complete with "No migrations were applied" and exit code 0 — idempotency ensured by `IF NOT EXISTS` on extension and index SQL and by `__EFMigrationsHistory` gate
  - pgvector extension not available: If the PostgreSQL container uses `postgres:15` instead of `pgvector/pgvector:pg15`, the migration must fail with `ERROR: could not open extension control file ...vector.control` — not silently create the column without the index

## Task Overview

After the entity model is complete (task_001), run `dotnet ef migrations add InitialSchema` to scaffold the initial migration file. Manually edit the generated `Up()` method to prepend `CREATE EXTENSION IF NOT EXISTS pgcrypto` and `CREATE EXTENSION IF NOT EXISTS vector` before the EF-generated `CreateTable` calls, and to append the `ivfflat` cosine index SQL after all table creation. Edit `Down()` symmetrically for safe rollback. The resulting migration, when applied via `dotnet ef database update`, must satisfy all five acceptance criteria and both edge cases.

## Implementation Plan
1. From the `src/api/` directory, run `dotnet ef migrations add InitialSchema` to generate the initial migration file; confirm the file appears at `src/api/Migrations/YYYYMMDDHHMMSS_InitialSchema.cs`
2. Open the generated migration file and locate the `Up()` method; prepend two `migrationBuilder.Sql()` calls before any `migrationBuilder.CreateTable()` call:
   - `migrationBuilder.Sql("CREATE EXTENSION IF NOT EXISTS pgcrypto;");`
   - `migrationBuilder.Sql("CREATE EXTENSION IF NOT EXISTS vector;");`
3. After all `migrationBuilder.CreateTable()` and `migrationBuilder.CreateIndex()` calls in `Up()`, append the ivfflat index creation:
   - `migrationBuilder.Sql("CREATE INDEX IF NOT EXISTS idx_chunk_embeddings_embedding_ivfflat ON chunk_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);");`
4. In the `Down()` method, add `migrationBuilder.Sql("DROP INDEX IF EXISTS idx_chunk_embeddings_embedding_ivfflat;");` before any `migrationBuilder.DropTable()` calls, and add `migrationBuilder.Sql("DROP EXTENSION IF EXISTS vector;");` and `migrationBuilder.Sql("DROP EXTENSION IF EXISTS pgcrypto;");` at the end of `Down()` after all DropTable calls
5. Verify that the 12 `CreateTable` names generated by EF Core match the AC-002 required names exactly (`users`, `patients`, `intake_records`, `appointment_slots`, `bookings`, `clinical_documents`, `extracted_records`, `chunk_embeddings`, `medical_code_suggestions`, `audit_logs`, `reminder_schedules`, `insurance_records`) — these are produced by `UseSnakeCaseNamingConventions()` from task_001; correct any discrepancies in entity naming before re-running the migration scaffold
6. Confirm the `bookings` table in the generated migration includes a `FK_bookings_patients_patient_id` constraint entry from EF Core's output — this validates that the Fluent API FK configured in task_001 is correctly reflected in the migration DDL

## Implementation Checklist
- [ ] `Up()` prepends `migrationBuilder.Sql("CREATE EXTENSION IF NOT EXISTS pgcrypto;")` and `migrationBuilder.Sql("CREATE EXTENSION IF NOT EXISTS vector;")` before the first `CreateTable` call (AC-001)
- [ ] `Up()` appends `migrationBuilder.Sql("CREATE INDEX IF NOT EXISTS idx_chunk_embeddings_embedding_ivfflat ON chunk_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);")` after all `CreateTable` and `CreateIndex` calls (AC-003)
- [ ] `Down()` contains `DROP INDEX IF EXISTS idx_chunk_embeddings_embedding_ivfflat` before any `DropTable` call and `DROP EXTENSION IF EXISTS vector/pgcrypto` after all `DropTable` calls — matching the reverse order of `Up()` (AC-001, AC-003 — rollback safety)
- [ ] Both extension statements and the index statement use `IF NOT EXISTS` / `IF EXISTS` so a second `dotnet ef database update` run exits cleanly with "No migrations were applied" and EF Core's `__EFMigrationsHistory` guard prevents re-execution (Edge: re-run idempotency)
- [ ] The generated migration contains a `FK_bookings_patients_patient_id` constraint definition in the `bookings` `CreateTable` call — confirming EF Core emitted the FK DDL from task_001's Fluent API config (AC-004)
- [ ] The `docker-compose.yml` `db` service uses image `pgvector/pgvector:pg15` (not `postgres:15`) — if the wrong image is used, the `CREATE EXTENSION vector` step will raise `ERROR: could not open extension control file` which explicitly surfaces the misconfiguration before any silent data loss (Edge: pgvector not available)
- [ ] After applying the migration, `SELECT migration_id FROM "__EFMigrationsHistory"` returns exactly one row whose `migration_id` ends with `_InitialSchema` — confirming EF Core registered the migration as applied (AC-005)
