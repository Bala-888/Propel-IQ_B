# User Story - US_007

## Story ID
* ID Format: US_007

## Story Title
* Seed InsuranceRecord dataset and wire no-show risk score and code suggestion schema fields

## Description
* As a **backend developer**, I want the `insurance_records` table seeded with a dummy validation dataset and the `bookings.no_show_risk_score` and `medical_code_suggestions` schema fields added with correct types, so that insurance pre-check, risk scoring, and code suggestion features have their data layer ready when their epics begin.

## Acceptance Criteria

### AC-001: `insurance_records` seed script inserts at least 10 dummy records
- **Given**: The database migration has completed
- **When**: The seed script (`dotnet run --project seed`) is executed
- **Then**: `SELECT COUNT(*) FROM insurance_records` returns ≥ 10 and at least one record has `provider_name = 'BlueCross BlueShield'`

### AC-002: `bookings.no_show_risk_score` column accepts integer 0–100
- **Given**: The `bookings` table schema includes `no_show_risk_score INTEGER` with a CHECK constraint `CHECK (no_show_risk_score BETWEEN 0 AND 100)`
- **When**: An INSERT with `no_show_risk_score = 75` is executed
- **Then**: The row is saved successfully

### AC-003: `bookings.risk_factors` JSONB column stores factor values
- **Given**: A booking record with risk factors `{"lead_time_days": 14, "prior_no_shows": 1, "channel": "online"}`
- **When**: `SELECT risk_factors FROM bookings WHERE id = <id>` is executed
- **Then**: The returned JSONB contains all three keys with their correct values

### AC-004: `medical_code_suggestions` review status defaults to Pending
- **Given**: An INSERT into `medical_code_suggestions` with no explicit `review_status` value
- **When**: `SELECT review_status FROM medical_code_suggestions WHERE id = <id>` is executed
- **Then**: The value is `Pending` (the column default)

### AC-005: `clinical_documents.file_hash` column stores SHA-256 hex string
- **Given**: A clinical document record is inserted with `file_hash = 'abc123...'` (64 hex chars)
- **When**: `SELECT LENGTH(file_hash) FROM clinical_documents WHERE id = <id>` is executed
- **Then**: The returned length is 64

## Edge Cases
* **Duplicate insurance record seed on re-run**: If the seed script is run a second time, it must use `INSERT ... ON CONFLICT DO NOTHING` to avoid duplicate rows rather than failing with a unique constraint violation.
* **Invalid `review_status` enum value**: If application code attempts to INSERT a `review_status` value not in `{Pending, Accepted, Rejected}`, PostgreSQL must raise a check constraint error rather than storing an invalid state.
