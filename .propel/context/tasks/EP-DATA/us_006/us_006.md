# User Story - US_006

## Story ID
* ID Format: US_006

## Story Title
* Implement PHI column encryption wrappers and append-only audit log database role

## Description
* As a **security engineer**, I want all PHI columns encrypted via pgcrypto `pgp_sym_encrypt` before persistence and the `audit_logs` table protected by an INSERT-only PostgreSQL role, so that PHI is unreadable at rest if storage volumes are accessed directly and audit records cannot be altered by any application-layer code.

## Acceptance Criteria

### AC-001: PHI fields encrypted before storage — plaintext absent from DB
- **Given**: A patient is created with `email = "test@example.com"` and `phone = "555-1234"`
- **When**: `SELECT email, phone FROM patients WHERE id = <id>` is executed directly against PostgreSQL as the `app_user` role
- **Then**: Both columns return pgcrypto ciphertext (bytea), not the original plaintext values

### AC-002: `IPhiEncryptionService` decrypts correctly in the .NET API
- **Given**: A patient record with encrypted PHI columns exists in the database
- **When**: `PatientRepository.GetByIdAsync(patientId)` is called from the .NET API
- **Then**: The returned `PatientDto` contains the original plaintext values for `email`, `phone`, `dateOfBirth`, `insuranceProvider`, and `insuranceId`

### AC-003: `app_user` database role cannot UPDATE or DELETE audit log records
- **Given**: The `app_user` PostgreSQL role is used by the .NET API
- **When**: An UPDATE or DELETE SQL statement is executed against `audit_logs` as `app_user`
- **Then**: PostgreSQL raises `ERROR: permission denied for table audit_logs` and the statement is rolled back

### AC-004: Encryption key injected via environment variable — not committed
- **Given**: The `PHI_ENCRYPTION_KEY` environment variable is set at container startup
- **When**: The `IPhiEncryptionService` is instantiated during DI container build
- **Then**: The key is read from the environment variable and stored in a `ReadOnlyMemory<byte>` field; no plaintext key appears in any log, config file, or codebase file

### AC-005: AuditLog INSERT succeeds for `app_user`
- **Given**: The `app_user` role is used and the audit log middleware fires
- **When**: An INSERT into `audit_logs` with valid required fields is executed
- **Then**: The row is persisted and `SELECT COUNT(*) FROM audit_logs` increases by 1

## Edge Cases
* **Encryption key rotation**: If `PHI_ENCRYPTION_KEY` changes between deployments, previously encrypted PHI columns become unreadable until re-encrypted with the new key. The application must detect a decryption failure and return HTTP 503 with message `PHI decryption failed — key rotation required` rather than returning garbled data.
* **Null or empty PHI field**: If a nullable PHI column (e.g., `insuranceId`) is NULL, `pgp_sym_encrypt(NULL, key)` must not be called — the column must remain NULL, not an encrypted null byte sequence.
