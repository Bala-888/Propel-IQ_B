# User Story - US_032

## Story ID
* ID Format: US_032

## Story Title
* Mark patient as arrived inline in the queue dashboard in 2 clicks or fewer

## Description
* As a **staff member**, I want to mark a patient as arrived directly from the queue row without navigating to another screen, so that patient status is updated instantly with minimal friction.

## Acceptance Criteria

### AC-001: "Mark Arrived" action is accessible from the queue row in one click
- **Given**: A patient in the queue has `status = "Waiting"`
- **When**: The staff member is viewing SCR-011
- **Then**: A "Mark Arrived" button (or icon button with an accessible label) is visible inline in the queue row — no navigation away from SCR-011 is required

### AC-002: Clicking "Mark Arrived" updates the row status in 2 clicks or fewer
- **Given**: The staff member clicks "Mark Arrived" on a queue row
- **When**: The action completes
- **Then**: `PATCH /queue/{queueEntryId}/arrived` is called, the response is HTTP 200 with `{"status": "Arrived", "arrivedAt": "<timestamp>"}`, the row status cell updates to "Arrived" in place, and the "Mark Arrived" button is hidden — all without leaving SCR-011; total user actions ≤ 2

### AC-003: Arrived time is recorded accurately on the queue entry
- **Given**: The staff member marks a patient as arrived at 10:34:07
- **When**: The PATCH call completes
- **Then**: The `queue_entries.arrived_at` column is set to within 5 seconds of the actual server-side time of the call — not the client's local time

### AC-004: Action is idempotent — repeated "Mark Arrived" on the same entry is safe
- **Given**: A queue entry already has `status = "Arrived"`
- **When**: `PATCH /queue/{queueEntryId}/arrived` is called again
- **Then**: The response is HTTP 200, `arrived_at` remains unchanged, and no duplicate audit log entry is created

## Edge Cases
* **Network failure after button click**: If the PATCH call fails with a network error or 5xx, the row must remain in its previous "Waiting" state and a toast must appear: "Could not mark as arrived. Please try again." — the button must reappear for retry.
* **Race condition — two staff mark the same patient simultaneously**: The `PATCH` must be idempotent (AC-004 above) so that the second call does not produce an error or data inconsistency.
