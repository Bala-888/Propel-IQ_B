# User Story - US_008

## Story ID
* ID Format: US_008

## Story Title
* Patient self-registration form and API endpoint

## Description
* As a **new patient**, I want to create my own account by providing my name, date of birth, contact information, and insurance details, so that I can access appointment booking and intake features without staff assistance.

## Acceptance Criteria

### AC-001: Successful registration creates a Patient account
- **Given**: No account exists for `email = "sarah.jones@email.com"`
- **When**: `POST /auth/register` is called with valid `name`, `dateOfBirth`, `email`, `phone`, `insuranceProvider`, and `insuranceId`
- **Then**: The response is HTTP 201 with `{"userId": "<uuid>", "role": "Patient"}` and a row exists in `patients` with the provided email (encrypted)
- **And**: An audit log entry with `ActionType: PatientRegistration` is written

### AC-002: Duplicate email registration rejected
- **Given**: An account already exists with `email = "sarah.jones@email.com"`
- **When**: `POST /auth/register` is called again with the same email
- **Then**: The response is HTTP 409 with `{"error": "An account with this email already exists"}` and no new row is created in `patients`

### AC-003: Missing mandatory field returns field-specific validation error
- **Given**: A registration payload is submitted without the `dateOfBirth` field
- **When**: `POST /auth/register` is called
- **Then**: The response is HTTP 400 with a `validationErrors` object containing `{"dateOfBirth": "Date of birth is required"}`
- **And**: No partial patient record is created in the database

### AC-004: React registration form displays inline validation errors
- **Given**: The user has submitted the registration form without entering a phone number
- **When**: The form validation fires on submit
- **Then**: A red error message "Phone number is required" appears directly below the phone field without a page reload
- **And**: The submit button becomes disabled while any validation error is displayed

### AC-005: Successful registration redirects to the intake screen
- **Given**: All form fields are valid and the API returns HTTP 201
- **When**: The registration form is submitted
- **Then**: The React SPA navigates to `/intake` and the new patient's name appears in the page header within 1 second

## Edge Cases
* **Invalid email format**: If `email` does not match a valid email pattern (e.g., `"notanemail"`), the API must return HTTP 400 with `{"email": "Must be a valid email address"}` before any database write occurs.
* **Date of birth in the future**: If `dateOfBirth` is later than today, the API must return HTTP 400 with `{"dateOfBirth": "Date of birth cannot be in the future"}`.
* **Insurance fields are optional**: If `insuranceProvider` and `insuranceId` are omitted, the registration must succeed and the patient's insurance fields must be NULL (not an empty string).
