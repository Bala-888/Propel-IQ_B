# User Story - US_011

## Story ID
* ID Format: US_011

## Story Title
* Admin user management CRUD — create, edit, deactivate, and assign roles

## Description
* As an **admin**, I want to create, edit, deactivate, and assign roles to user accounts from the admin console, so that I can govern access to the platform without requiring database access.

## Acceptance Criteria

### AC-001: Admin creates a new Staff user account
- **Given**: An Admin is authenticated and on the User Management screen (SCR-017)
- **When**: The admin clicks "New User", fills in name, email, and selects role `Staff`, and submits the Create/Edit User modal (MOD-006)
- **Then**: The API `POST /admin/users` creates a new user record, the new user appears in the user table, and an audit log entry with `ActionType: UserCreated` is written
- **And**: The new user receives a "Welcome, your account has been created" email with temporary credentials

### AC-002: Admin edits an existing user's role
- **Given**: A user with `role = "Patient"` exists
- **When**: The admin opens MOD-006 for that user, changes the role to `Staff`, and saves
- **Then**: `PATCH /admin/users/<id>` updates the `role` field and the role change is visible immediately in the user table
- **And**: An audit log entry with `ActionType: RoleChanged` and `{"from": "Patient", "to": "Staff"}` is written

### AC-003: Admin deactivates a non-admin user account
- **Given**: An active Staff user account exists
- **When**: The admin clicks "Deactivate" in the user table row and confirms the dialog
- **Then**: `PATCH /admin/users/<id>` sets `isActive = false`, the user can no longer authenticate (receives HTTP 401), and an audit log entry with `ActionType: UserDeactivated` is written

### AC-004: Admin cannot deactivate their own account
- **Given**: The logged-in admin's row is displayed in the user table
- **When**: The Deactivate button for the admin's own row is rendered
- **Then**: The button is `aria-disabled="true"` and clicking it shows an error banner "You cannot deactivate your own account" without calling the API

### AC-005: Duplicate email on user creation is rejected
- **Given**: A user with `email = "jane@clinic.com"` already exists
- **When**: The admin attempts to create another user with the same email via the modal form
- **Then**: `POST /admin/users` returns HTTP 409 and the modal displays "A user with this email already exists" inline without closing

## Edge Cases
* **Reactivating a deactivated user**: An admin must be able to set `isActive = true` for a deactivated user. The user must then be able to log in on the next attempt.
* **Invalid role value submitted via API**: If a `PATCH /admin/users/<id>` request contains a `role` value not in `{Patient, Staff, Admin}`, the API must return HTTP 400 with `{"role": "Invalid role value"}` without updating the record.
