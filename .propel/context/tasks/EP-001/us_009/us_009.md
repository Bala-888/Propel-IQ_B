# User Story - US_009

## Story ID
* ID Format: US_009

## Story Title
* Multi-role login with JWT Bearer tokens and role-based dashboard redirect

## Description
* As an **authenticated user (Patient, Staff, or Admin)**, I want to sign in with my email and password and be automatically routed to my role-appropriate dashboard, so that I can access only the features relevant to my role without manual navigation.

## Acceptance Criteria

### AC-001: Successful login returns a JWT with role claim
- **Given**: An active user with `email = "dr.chen@clinic.com"` and `role = "Staff"` exists in the database
- **When**: `POST /auth/login` is called with the correct credentials
- **Then**: The response is HTTP 200 with `{"accessToken": "<jwt>", "refreshToken": "<uuid>", "role": "Staff"}` and the JWT's `role` claim equals `Staff`
- **And**: The access token expires in exactly 15 minutes (verified via `exp` claim)

### AC-002: Patient is redirected to `/intake` after login
- **Given**: A Patient user logs in successfully
- **When**: The React SPA receives the JWT response and decodes the role claim
- **Then**: The browser navigates to `/intake` (or the stored `redirect` path if present) within 500 ms

### AC-003: Staff is redirected to `/queue` after login
- **Given**: A Staff user logs in successfully
- **When**: The React SPA processes the role claim
- **Then**: The browser navigates to `/queue` within 500 ms

### AC-004: Admin is redirected to `/admin` after login
- **Given**: An Admin user logs in successfully
- **When**: The React SPA processes the role claim
- **Then**: The browser navigates to `/admin` within 500 ms

### AC-005: Invalid credentials return a generic error — no account existence leak
- **Given**: A login attempt with `email = "attacker@evil.com"` (non-existent) or with a wrong password for an existing account
- **When**: `POST /auth/login` is called
- **Then**: The response is HTTP 401 with `{"error": "Invalid email or password"}` in both cases — the error message is identical regardless of whether the email exists
- **And**: An audit log entry with `ActionType: LoginFailure` is written

### AC-006: Deactivated user account is rejected at login
- **Given**: A user account with `isActive = false`
- **When**: `POST /auth/login` is called with correct credentials
- **Then**: The response is HTTP 401 with `{"error": "Account is inactive. Please contact your administrator."}`

## Edge Cases
* **JWT token used after expiry**: If an expired access token is sent to a protected endpoint, the API must return HTTP 401 with `{"error": "Token expired"}` — not HTTP 403, to allow the client to trigger a token refresh flow.
* **Refresh token reuse after rotation**: If a refresh token is submitted after it has already been rotated (replay attack), the API must invalidate the entire token family and return HTTP 401 with `{"error": "Refresh token reuse detected"}`.
